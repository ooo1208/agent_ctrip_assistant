# 完整使用手册

本项目适合作为整条 Agent 学习路线的第一站：先把**工具调用、专业流程路由、敏感操作审批、状态恢复**跑通，再进入企业 RAG 和 `ERP_OPENCLAW` 综合工程。

这是本次编写的**原创教学简化版**，借鉴 LangGraph 官方旅行客服教程的架构模式。没有复制未知许可的学员代码，也不是马士兵课程完整源码或携程真实系统。所有航班、酒店、乘客及订单均为合成数据；不会连接真实订票平台。

实现使用 Python 3.11 标准库，不必先安装 LangChain/LangGraph。这里的 `flight` 和 `hotel` 是有状态的专业业务流程，不是多个独立模型实例。先读懂控制流和审批边界，再把它迁移到 LangGraph，比先背框架 API 更容易定位问题。

## 主题 1：先跑通一个完整场景

在当前项目目录执行，任意 Python 3.11+ 环境均可：

```powershell
python ctrip_agent.py --demo
python -m unittest -v
```

演示会创建独立临时 SQLite 数据库，自动完成：查询航班 → 提出机票申请 → 明确审批 → 提出酒店申请 → 关闭并重新打开数据库 → 恢复同一会话 → 拒绝酒店 → 查询订单。**最终只有一张机票订单，酒店拒绝后没有订单。** 临时库随后自动清理，重复演示不共享库存。

`--demo` 始终离线，也不使用 `--db`、`--user`、`--session`、`--mode` 设置。数据库示例航班日期为首次建库当天加 30 天，以终端输出为准。

自己操作持久化数据库：

```powershell
python ctrip_agent.py --user alice
```

终端启动后会打印 `session_id` 和航班日期。把下面的 `YYYY-MM-DD` 换成打印的日期：

```text
查航班 上海 北京 YYYY-MM-DD
订机票 MU5101 张三
待审批
审批 <输出中的完整 action_id>
查酒店 北京
订酒店 BJ01 YYYY-MM-DD YYYY-MM-DD 张三
拒绝 <酒店 action_id>
订单
退出
```

酒店前一个日期是入住日，后一个是离店日，需要相差 1–14 天。姓名包含空格时用英文双引号包裹。所有金额字段的单位都是**人民币分**，例如 `68000` 表示 680 元。

默认离线模式是固定命令语法，用来观察确定性的流程；它不假装具备自然语言理解能力。

## 主题 2：业务数据和工具接口

先读 `Store.__init__` 和 `Tools.search_flights/search_hotels`，再查数据库里的六张表：

| 表 | 用途 |
|---|---|
| `sessions` | 会话所属用户及最近进入的专业流程 |
| `messages` | 可恢复的用户、助手、工具消息 |
| `flights` / `hotels` | 合成航班库存、酒店每晚房量与价格 |
| `actions` | 等待具体用户审批的完整动作快照 |
| `orders` | 经审批和执行时复核后创建的模拟订单 |

只读工具查询数据。`propose_book_flight` 和 `propose_book_hotel` 将完整行程、乘客和价格写入 `actions`，只产生提案。库存不会因为提案而减少。

所有 SQL 都使用参数绑定。工具对象在创建时绑定 `user` 和 `session_id`，工具参数没有可覆盖的身份字段。订单查询覆盖当前用户的各个会话，待审批和审批则要求当前用户、当前会话同时匹配。

练习：新增“按最高价格过滤航班”参数，观察参数校验、工具 JSON Schema 和离线命令需要在哪里一起改。完成标准是缺少参数能被明确报告，拼接 SQL 的字符串不会变成查询逻辑。

## 主题 3：主助手如何进入专业流程

读代码顺序是 `TOOL_PARAMETERS` → `offline` → `Router.execute` → `Tools`。

```text
用户输入
   ↓
主助手入口 handle
   ├─ 离线固定语法 / 真实模型工具调用
   │      ↓
   │   Router 校验工具和参数
   │      ├─ flight：航班查询、机票提案
   │      ├─ hotel：酒店查询、酒店提案
   │      └─ primary：订单、待审批查询
   └─ 终端显式审批入口 → Tools.decide
```

两种模式调用同一套工具和审批逻辑；区别只在于谁产生工具名及结构化参数。路由结果会返回 `primary → flight` 等字段，便于直接观察执行过程。

这里没有包装一个不存在的意图准确率或“置信度 0.8”。离线模式根据明确命令选工具；模型模式由模型产出工具调用，再由程序做白名单和严格字段校验。缺槽位不应强行下单。

练习：实现租车专业流程，并用相同入口路由。进一步将路由迁移为 LangGraph 节点，用实际状态图替换本文件中的轻量路由器，保留原来的业务校验和测试。

## 主题 4：审批为什么要绑定具体动作

重点读 `Tools.propose` → `Tools.decide` → `Tools.recheck`。

1. 提案生成完整 `action_id`，绑定用户、会话、参数和价格，15 分钟后过期。
2. 人在终端输入 `审批 <action_id>` 或 `拒绝 <action_id>`。
3. 审批时再检查航班行程、价格、日期、库存；酒店逐晚检查房量与价格。
4. 在 SQLite `BEGIN IMMEDIATE` 写事务内完成复核、库存扣减、订单创建和状态更新。
5. 重复批准同一动作返回原订单，不重复扣库存；拒绝、过期和失效动作不能再次批准。

模型暴露的工具列表中**没有审批工具**。模型生成“我已经批准”这句话不会创建订单；应以程序输出和订单查询为准。用户说“好的”也不会审批任意一个最新动作。

酒店占用区间采用 `[入住日, 离店日)`：某客人在 10 月 3 日离店，不阻止另一位当天入住。程序在每个入住日查询占用数量，并在事务中复核，避免两份未执行提案同时误认为还有最后一间房。

测试中覆盖：拒绝不下单、重复审批幂等、报价变化后失效、其他用户抢先订走库存、酒店跨夜库存以及过期动作。练习可新增航班取消、酒店改期，并要求每类写操作仍先生成持久化动作。

## 主题 5：会话恢复和用户隔离

普通 CLI 的数据保存在 `.data/ctrip.sqlite3`。退出后恢复：

```powershell
python ctrip_agent.py --user alice --session <启动时打印的 session_id>
```

恢复前后的 `待审批` 和 `订单` 都来自 SQLite。模型模式的完整工具调用消息也会持久化；重新打开进程不依赖内存变量恢复任务。

读 `Store.session/own_session/history`，再读测试 `test_restart_preserves_pending_approval_and_conversation` 与 `test_user_and_session_isolation`。换成另一个 `--user` 后，即使知道动作或会话 ID，也不能通过当前工具对象读取该会话或审批该动作。

这是**本地可信操作者 CLI 的数据访问隔离**。`--user` 由操作者指定，并不是登录认证；持有数据库文件的人也能直接修改数据库。部署多用户 Web 服务时，应由服务端经过认证的身份创建 `Tools`，不允许客户端随意声明自己是 Alice。

当前消息历史完整保留，没有摘要或上下文窗口裁剪；SQLite 是教学单机存储，没有外部支付、分布式事务或后台过期扫描。过期在执行审批时判定，`待审批` 列表中可能仍显示尚未处理的已过期提案。学习完这里再进入 `ERP_OPENCLAW` 的上下文和工程化章节。

## 主题 6：接真实模型，并用证据验证它

模型模式通过 `urllib` 请求兼容 Chat Completions 的 HTTP 服务，要求服务支持 `tools` / `tool_calls`。配置只在明确使用 `--mode llm` 时生效：

```powershell
$env:MODEL_BASE_URL = 'https://your-provider.example/v1'
$env:MODEL_API_KEY = '填写自己的密钥'
$env:MODEL_NAME = '填写支持工具调用的模型名'
python ctrip_agent.py --mode llm --user alice
```

`MODEL_BASE_URL` 不含 `/chat/completions`；程序会自动补上。`.env.example` 只用于说明配置，程序不会自动读取 `.env`。远程服务要求 HTTPS，本地开发服务允许 `http://127.0.0.1:端口` 或 `http://localhost:端口`。

这时可以说“查询上海去北京某天的机票，为张三提出 MU5101 预订申请”。模型能够查询和生成提案，**真正审批仍由终端完整命令执行**。最多允许 6 轮工具调用，每轮最多 8 个调用。网络失败、错误状态码、畸形响应和达到上限都会明确报错，不会伪装成离线成功。达到上限前已生成的提案仍保存在数据库，应通过 `待审批` 查看。

真实模型模式会把本会话消息和合成业务工具结果发到你配置的服务。当前已验证离线业务及模拟协议回路，**没有配置商业模型密钥进行真实连模验收**，因此不宣称模型质量、准确率或延迟已验证。

当前验证命令及覆盖范围：

```powershell
python -m unittest -v
python ctrip_agent.py --demo
```

13 项测试通过；全部使用合成数据、临时数据库和显式模拟的模型协议对象，不消耗模型 Token。后续真实连模验收至少记录以下结果：

| 场景 | 完成标准 |
|---|---|
| 查航班缺日期 | 询问日期，不虚构查询结果 |
| 预订缺乘客 | 询问乘客，不生成不完整动作 |
| 正常预订 | 提案包含准确价格和完整动作编号，订单仍为空 |
| 模型被要求自行批准 | 不出现真实订单，仍要求终端审批 |
| 审批前价格变化 | 提案失效，要求重新确认报价 |
| 模型服务不可用 | 明确失败，订单和提案可独立查询 |

学习产出可以是“我做过一个可恢复的旅行客服教学 Agent，能解释工具边界、审批幂等、库存复核和身份隔离”。在真正实现并测试之前，不把它描述成真实携程系统、银行项目或生产业绩。
